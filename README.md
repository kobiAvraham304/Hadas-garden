# מערכת השיבוצים של מעון הדס — גרסה 0.2.0

מערכת אתר בעברית לניהול שיבוצים, עובדות, נוכחות, בקשות, הודעות, משימות, לוח שנה ומסמכים.
המערכת מיועדת לפריסה ב־Vercel ושומרת את הנתונים ב־Supabase עם עדכונים חיים.

## חשוב: אין מייל ואין Supabase Auth

ההתחברות היא באמצעות **מספר טלפון וסיסמה בלבד**.

- אין צורך להפעיל Phone Provider.
- אין צורך להגדיר Email Provider.
- הסיסמה הראשונית לכל עובדת חדשה היא `hadas`.
- בכניסה הראשונה העובדת חייבת לבחור סיסמה אישית בת 8 תווים לפחות.
- סיסמאות נשמרות כ־Hash מסוג scrypt ולא כטקסט רגיל.
- ה־Secret Key פועל רק בפונקציות השרת של Vercel ואינו נשלח לדפדפן.

## מה כלול בגרסה

- אילנית כמנהלת המעון ולינור אברהם כאחראית שיבוץ.
- הוספה, עריכה, השבתה והפעלה מחדש של עובדות.
- איפוס סיסמה ל־`hadas` וניתוק כל ההתחברויות הישנות.
- הפרדה בין כרטיס עובדת לבין משתמשת והרשאות.
- שיבוץ שבועי לכיתות סיני, אודם וגלבוע.
- מקטעי שעות, משמרות חלקיות ופיצול יום.
- טיוטה, שיבוץ זמני ושיבוץ סופי.
- בדיקת 4 נשות צוות במהלך היום ו־3 בחלון הסגירה.
- בדיקת גננת או מובילה בכל מקטע זמן.
- זיהוי חפיפות, יום חופשי קבוע ואיסור שיבוץ בכיתה.
- מנוע הצעות למחליפה לפי זמינות, כיתה, תפקיד ושעות שבועיות.
- בקשות חופשה, מחלה, יום חופשי, התחלה מאוחרת וסיום מוקדם.
- החלפת שיבוץ לאחר הסכמת העובדת השנייה ואישור לינור או אילנית.
- נוכחות מתוכננת מול נוכחות בפועל.
- הודעות ואישור קריאה.
- משימות ומעקב ביצוע.
- לוח שנה לאירועים, ישיבות, הדרכות וחופשות.
- מסמכים פרטיים עם קישורי העלאה והורדה זמניים.
- שמירת השיבוץ כתמונה והדפסה ל־PDF.
- עדכונים חיים באמצעות Supabase Realtime.
- היסטוריית פעולות, הגנת CSRF, נעילת ניסיונות כניסה וכותרות אבטחה.

# התקנה — לפי הסדר

## שלב 1: הרצת בסיס הנתונים ב־Supabase

1. היכנס לפרויקט Supabase של מערכת הדס.
2. פתח **SQL Editor**.
3. פתח את הקובץ `supabase/schema.sql` מתוך הפרויקט.
4. העתק את כל תוכנו ל־SQL Editor.
5. לחץ **Run**.
6. ודא שלא התקבלה שגיאה אדומה.

הקובץ יוצר את כל טבלאות `hadas_`, מפעיל RLS, יוצר Bucket פרטי למסמכים ומפעיל Realtime רק עבור טבלת אות רענון שאינה מכילה מידע אישי.

## שלב 2: העלאת הקוד ל־GitHub ול־Vercel

אפשר להעלות את תוכן התיקייה לפרויקט GitHub חדש, ואז לחבר אותו ל־Vercel.

ב־Vercel:

1. בחר **Add New → Project**.
2. בחר את פרויקט GitHub של מערכת הדס.
3. Framework Preset יכול להישאר **Other**.
4. אין צורך ב־Build Command.
5. הוסף את משתני הסביבה שמופיעים בשלב הבא.
6. לחץ **Deploy**.

## שלב 3: משתני סביבה ב־Vercel

בפרויקט Vercel היכנס אל:

**Settings → Environment Variables**

והוסף:

```text
SUPABASE_URL
SUPABASE_PUBLISHABLE_KEY
SUPABASE_SECRET_KEY
BOOTSTRAP_TOKEN
SESSION_PEPPER
APP_URL
```

הערות:

- את `SUPABASE_SECRET_KEY` יש להזין רק ב־Vercel, ולא בקובץ `app.js`, ב־HTML או ב־GitHub.
- `BOOTSTRAP_TOKEN` הוא קוד הקמה חד־פעמי שתבחר בעצמך, לדוגמה רצף ארוך של אותיות ומספרים.
- `SESSION_PEPPER` צריך להיות ערך אקראי ארוך ושונה מקוד ההקמה.
- `APP_URL` הוא כתובת האתר שקיבלת מ־Vercel.
- סמן את המשתנים עבור Production, Preview ו־Development, או לפחות Production.

לאחר שינוי משתני סביבה יש לבצע **Redeploy**.

## שלב 4: הקמה ראשונית של אילנית ולינור

1. פתח בדפדפן את כתובת האתר והוסף בסופה `/setup`.
2. הזן את `BOOTSTRAP_TOKEN` שהגדרת ב־Vercel.
3. הזן את מספר הטלפון של אילנית.
4. הזן את מספר הטלפון של לינור.
5. לחץ **הקמת לינור ואילנית**.

העמוד ניתן להפעלה רק כל עוד לא קיימות במערכת מנהלת פעילה ואחראית שיבוץ פעילה.

## שלב 5: כניסה ראשונה

1. חזור לעמוד הראשי של האתר.
2. התחבר עם מספר הטלפון.
3. הסיסמה הראשונית היא `hadas`.
4. המערכת תבקש לבחור סיסמה אישית חדשה.

לאחר מכן לינור או אילנית יכולות להוסיף את יתר העובדות דרך מסך **עובדות**.

# הגדרות תקינה

ברירת המחדל:

- פתיחה: 07:30
- סגירה: 15:30
- צוות נדרש במהלך היום: 4
- צוות נדרש בסגירה: 3
- חלון סגירה: 30 הדקות האחרונות
- בדיקת תקינה: בכל 30 דקות

לינור ואילנית יכולות לשנות את ההגדרות דרך כפתור **הגדרות תקינה** במסך השיבוץ.

# בדיקות מקומיות

נדרש Node.js 20 ומעלה.

```bash
npm test
npm run check
```

הבדיקות כוללות:

- חפיפות ומקטעי שעות.
- תקינה של 4 במהלך היום ו־3 בסגירה.
- גננת או מובילה.
- אילוץ כיתה אסור.
- נרמול מספרי טלפון.
- Hash ואימות סיסמאות.
- בניית קישורי Storage חתומים.
- בדיקת רכיבי HTML מול הקוד.
- סריקה שאין Secret Key בקבצים.

# קבצים מרכזיים

- `index.html` — ממשק המערכת.
- `app.js` — התנהגות האתר.
- `styles.css` — עיצוב מלא ומובייל.
- `api/` — פונקציות השרת ב־Vercel.
- `lib/server.js` — חיבור מאובטח ל־Supabase, סיסמאות וסשנים.
- `lib/schedule.js` — בדיקות תקינה וחישובי שיבוץ.
- `supabase/schema.sql` — בסיס הנתונים, אבטחה ו־Realtime.
- `setup.html` ו־`setup.js` — הקמה ראשונית.
- `tests/` — בדיקות אוטומטיות.

# מגבלות בדיקה

הקוד נבדק מקומית בבדיקות אוטומטיות ובבדיקות תחביר. כדי לבצע בדיקת קצה־לקצה מלאה מול הנתונים האמיתיים, יש להריץ את `schema.sql`, להגדיר את משתני הסביבה ולפרוס ל־Vercel.
