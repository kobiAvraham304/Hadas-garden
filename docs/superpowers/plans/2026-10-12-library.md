# Hadas library 0.40.0 implementation plan

> Execute inline with superpowers:executing-plans. User approved the in-chat design and explicitly instructed implementation; do not add another approval gate. Use one fresh review at completion.

**Goal:** A private, mobile-first shared educational library for every active Hadas employee, and targeted system UX improvements.
**Architecture:** Keep the existing vanilla JS frontend, cookie sessions, unified API and Supabase. Add an independent library module, private signed direct uploads and SQL aggregation; never put files into the global scheduling payload.
**Tech Stack:** JavaScript, Node test runner, Postgres, Supabase Storage, Vercel.
**Spec:** Approved in-chat design dated 2026-10-12: cards, search/category filters, comments, like/tried, private collections, multiple attachments, previews, downloads/sharing, owner editing and manager moderation.

## Constraints
- Existing roles and scheduling rules remain authoritative. Library creation is allowed to every authenticated active employee.
- 10 files per post; 50MiB per file; allow common images including HEIC, audio, video, Office, PDF, text, open-document and archives; no HTML/SVG/executables.
- No public storage. Validate session, CSRF, ownership and committed uploads server-side.
- Make one production release after tests. Use 0.40.0 and retain the existing single Vercel function.
- Respect reduced motion; no new broad MutationObserver or permanent layout animation.
